# Регламент: Фрод и манипуляции

## Цель
Выявлять координированные и искусственные действия по накрутке рейтинга, включая фабрики отзывов, повторное использование контента и аномальное поведение аккаунтов.

## Технические зависимости и контракт
- `text_cluster_score`: вероятность принадлежности отзыва к известному шаблонному кластеру `0.0..1.0`.
- `image_perceptual_hash`: pHash/dHash изображения для поиска переиспользования.
- `image_reuse_count`: число уникальных аккаунтов/объектов с тем же изображением за окно.
- `account_risk_features`: признаки аккаунта `{age_days, reviews_count, verified_purchase_ratio, geo_jitter_score}`.
- `burst_signal`: число публикаций в коротком окне времени (`N` за `T` минут).
- `network_affinity_score`: сходство по устройствам/IP/поведенческим признакам `0.0..1.0`.

Минимальный формат:
```json
{
  "text_cluster_score": 0.88,
  "image_reuse_count": 12,
  "burst_signal": {"count": 20, "window_min": 15},
  "account_risk_features": {"age_days": 2, "verified_purchase_ratio": 0.0}
}
```

## Термины и определения
- **Координированный фрод**: группа отзывов, управляемая единым сценарием/оператором.
- **Накрутка**: искусственное изменение репутационных метрик через нерепрезентативные отзывы.
- **Поведенческий burst**: неестественный всплеск однотипных публикаций за короткий период.
- **Слабый сигнал**: отдельный индикатор, недостаточный для `REJECT` без подтверждений из других источников.

## Нормализация входа
- Текст: lowercase, удаление незначимых вариаций, выделение устойчивых n-грамм.
- Изображения: нормализация размера/цветового пространства перед расчетом хеша.
- Временные признаки приводятся к единой TZ и фиксированным окнам (`5/15/60` минут).

## Алгоритм проверки
1. Рассчитать текстовую шаблонность (`text_cluster_score`) и размер кластера.
2. Проверить переиспользование изображений через perceptual hash.
3. Оценить burst-активность по публикациям в окнах времени.
4. Рассчитать риск аккаунта (молодой возраст, отсутствие подтвержденных покупок, резкие сдвиги гео/девайса).
5. Слить сигналы в единый риск-профиль:
- высокий риск: >= 2 сильных сигнала;
- средний риск: 1 сильный + 1 слабый;
- низкий риск: только слабые/единичные аномалии.
6. Принять решение по детерминированной таблице.

## Таблица решений (детерминированная)
- `REJECT`:
- Есть `FRAUD_TEMPLATE_CLUSTER` с `text_cluster_score >= 0.85` и `cluster_size >= 5`.
- Или `FRAUD_IMAGE_REUSE` с `image_reuse_count >= 5` на разных аккаунтах.
- Или `FRAUD_BURST_ACTIVITY` + высокий `network_affinity_score >= 0.80`.
- `REVIEW`:
- Есть один сильный сигнал без подтверждения вторым независимым сигналом.
- Или несколько слабых сигналов в сумме (молодой аккаунт + подозрительная частота).
- `APPROVE`:
- Нет фрод reason-кодов.
- Наблюдаемые аномалии объяснимы органическим событием (распродажа, массовая доставка), без координации.

## Приоритеты и мультиразметка
- Формат: `primary_reason_code` + `secondary_reason_codes[]`.
- Приоритет:
1. `FRAUD_TEMPLATE_CLUSTER`
2. `FRAUD_IMAGE_REUSE`
3. `FRAUD_BURST_ACTIVITY`
4. `FRAUD_SUSPICIOUS_ACCOUNT`
- Если совпали текстовый и поведенческий сигналы, первичным является более устойчивый (обычно кластерный текст).

## Reason codes
- `FRAUD_TEMPLATE_CLUSTER`: отзыв принадлежит подтвержденному шаблонному кластеру накрутки.
- `FRAUD_IMAGE_REUSE`: изображение массово переиспользуется в нерелевантных отзывах.
- `FRAUD_BURST_ACTIVITY`: неестественный всплеск публикаций с однотипными признаками.
- `FRAUD_SUSPICIOUS_ACCOUNT`: профиль аккаунта демонстрирует высокорисковое, неорганичное поведение.

## Примеры
- `REJECT`: 30 отзывов за 20 минут с почти одинаковым текстом и новыми аккаунтами.
- `REJECT`: одно и то же фото чека в отзывах к разным объектам.
- `REVIEW`: новый аккаунт с 3 похожими отзывами за день без иных подтверждений.
- `APPROVE`: короткие, похожие отзывы после реального массового релиза товара.

## Edge cases
- Сезонные всплески должны сверяться с бизнес-событиями (акции, сбои, выход продукта).
- Переиспользование брендовых промо-изображений не всегда фрод, если это официальный контент объекта.
- Молодой аккаунт сам по себе не основание для `REJECT`.
- Низкая информативность текста относится к релевантности, а не автоматически к фроду.

## Тестовая матрица
- T1: `text_cluster_score=0.9`, `cluster_size=12` -> `REJECT`, `FRAUD_TEMPLATE_CLUSTER`.
- T2: `image_reuse_count=8` на разных аккаунтах -> `REJECT`, `FRAUD_IMAGE_REUSE`.
- T3: burst + affinity >= 0.8 -> `REJECT`, `FRAUD_BURST_ACTIVITY`.
- T4: только молодой аккаунт без иных сигналов -> `REVIEW`, `FRAUD_SUSPICIOUS_ACCOUNT`.
- T5: органический всплеск без шаблонности -> `APPROVE`.
- T6: повтор фото официального баннера -> `REVIEW` или `APPROVE` по контексту.
- T7: два слабых сигнала (погранично) -> `REVIEW`.
- T8: FN-контроль: кластер с мелкими вариациями текста должен обнаруживаться.
