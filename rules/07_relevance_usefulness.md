# Регламент: Релевантность и полезность

## Цель
Публиковать отзывы, которые содержат значимую информацию о пользовательском опыте и относятся к объекту отзыва, отсекая бессодержательный мусор и оффтоп.

## Технические зависимости и контракт
- `topic_match_score`: релевантность текста объекту/категории `0.0..1.0`.
- `information_density_score`: информативность текста `0.0..1.0` (факты, детали, причинно-следственные связи).
- `garbage_text_detector`: бинарный сигнал шумового текста (набор символов, бессмысленные повторы).
- `image_relevance_score`: релевантность изображений объекту `0.0..1.0`.
- `minimal_length_policy`: порог минимальной длины с учетом допустимых коротких отзывов.

Минимальный формат:
```json
{
  "topic_match_score": 0.82,
  "information_density_score": 0.41,
  "image_relevance_score": 0.33,
  "garbage_text_detector": false
}
```

## Термины и определения
- **Релевантность**: связь содержания с конкретным объектом отзыва (товар/услуга/продавец).
- **Полезность**: наличие деталей, которые помогают другим пользователям принять решение.
- **Бессодержательный отзыв**: текст без фактов/оценки опыта, только общие слова или шум.
- **Оффтоп**: контент, обсуждающий сторонние темы, не относящиеся к объекту.

## Нормализация входа
- Lowercase, очистка повторов символов и пробельного шума.
- Сохранение пунктуации и числовых данных (цена, срок, количество) как маркеров полезности.
- Обработка OCR-текста на изображениях для оценки тематического соответствия.

## Алгоритм проверки
1. Рассчитать `topic_match_score` по тексту и метаданным объекта.
2. Рассчитать `information_density_score`.
3. Проверить на `garbage_text_detector`.
4. Оценить релевантность изображений (`image_relevance_score`).
5. Применить правила:
- низкий topic + низкая информативность -> высокий риск;
- высокий topic и хотя бы средняя информативность -> допустимо;
- пограничные случаи с короткими, но смысловыми отзывами -> `APPROVE`.
6. Принять решение по таблице.

## Таблица решений (детерминированная)
- `REJECT`:
- `REL_GARBAGE_TEXT` (бессмысленный набор символов/слов).
- Или `REL_OFFTOPIC` при `topic_match_score < 0.35`.
- Или одновременно `REL_LOW_INFORMATION` + `REL_IRRELEVANT_IMAGE`.
- `REVIEW`:
- `topic_match_score` в диапазоне `0.35..0.55`.
- Или информативность пограничная (`0.25..0.40`) без явного шума.
- Или изображение спорно релевантно при нормальном тексте.
- `APPROVE`:
- Текст релевантен объекту и содержит хотя бы минимальную полезную конкретику.
- Короткий отзыв допустим, если выражает понятный опыт (`"доставили вовремя, упаковка целая"`).

## Приоритеты и мультиразметка
- Формат: `primary_reason_code` + `secondary_reason_codes[]`.
- Приоритет:
1. `REL_GARBAGE_TEXT`
2. `REL_OFFTOPIC`
3. `REL_LOW_INFORMATION`
4. `REL_IRRELEVANT_IMAGE`
- Если есть шум и оффтоп одновременно, первичный код `REL_GARBAGE_TEXT`.

## Reason codes
- `REL_OFFTOPIC`: содержание не относится к объекту/предмету отзыва.
- `REL_LOW_INFORMATION`: отзыв по теме, но недостаточно полезен (нет фактов/деталей).
- `REL_GARBAGE_TEXT`: бессмысленный или технический мусорный текст.
- `REL_IRRELEVANT_IMAGE`: изображение не связано с предметом отзыва.

## Примеры
- `REJECT`: "asdf qwe 123 !!!".
- `REJECT`: обсуждение политики в отзыве о доставке без связи с опытом.
- `REVIEW`: "норм" без деталей, но по теме.
- `APPROVE`: "доставили за 2 дня, упаковка помята, товар рабочий".

## Edge cases
- Очень короткие, но предметные отзывы не должны автоматически уходить в `REJECT`.
- Эмоциональная оценка без фактов может быть `REVIEW`, если есть тематическая связь.
- Нерелевантное изображение при хорошем тексте не всегда блокирует публикацию.
- Разговорный стиль и ошибки не считаются мусором при наличии смысла.

## Тестовая матрица
- T1: topic_match 0.2 -> `REJECT`, `REL_OFFTOPIC`.
- T2: garbage detector true -> `REJECT`, `REL_GARBAGE_TEXT`.
- T3: короткий, но конкретный отзыв -> `APPROVE`.
- T4: topic_match 0.5 и низкая конкретика -> `REVIEW`, `REL_LOW_INFORMATION`.
- T5: релевантный текст + нерелевантное фото -> `REVIEW`, `REL_IRRELEVANT_IMAGE`.
- T6: релевантный и детальный отзыв -> `APPROVE`.
- T7: FP-контроль: разговорный сленг по теме -> `APPROVE`.
- T8: FN-контроль: шаблонный мусор должен уходить в `REJECT`.
