# Регламент: Обход фильтров и технические аномалии

## Цель
Выявлять попытки скрыть нарушение за счет обфускации, кодирования и шумовых техник, не наказывая легитимный креативный стиль.

## Технические зависимости и контракт
- `obfuscation_detector`: сигналы обхода `leet|word_split|mixed_alphabet|homoglyph|zero_width`.
- `emoji_spam_score`: интенсивность emoji-шума `0.0..1.0`.
- `url_obfuscation_detector`: выявление скрытых URL (`hxxp`, `dot`, скрытые разделители и т.п.).
- `decode_attempts`: результаты декодирования base64/hex/morse/rot с confidence.
- `ocr_result`: текст на изображениях для поиска визуальной обфускации.
- `payload_violation_score`: вероятность того, что после декодирования обнаруживается нарушение из других регламентов.

Минимальный формат:
```json
{
  "obfuscation_detector": ["leet", "mixed_alphabet"],
  "emoji_spam_score": 0.82,
  "payload_violation_score": 0.91
}
```

## Термины и определения
- **Обфускация**: намеренное искажение текста для обхода детекторов.
- **Техническая аномалия**: нетипичная форма записи без доказанного запрещенного payload.
- **Нарушающий payload**: смысловое содержимое после нормализации/декодирования нарушает другой регламент.
- **Невосстановимый код**: последовательность, которую нельзя надежно декодировать.

## Нормализация входа
- Приведение mixed alphabet к канонической форме (кириллица/латиница/homoglyph).
- Удаление zero-width символов и служебных разделителей.
- Склейка искусственных разрывов слов (`в . о . й . н . а` -> `война`) для оценки payload.
- Нормализация URL-обфускаций (`hxxp`, `[dot]`, `d0t`) в стандартный URL.

## Алгоритм проверки
1. Вычислить сигналы obfuscation по тексту и OCR-тексту изображений.
2. Выполнить безопасные попытки декодирования для стандартных схем.
3. Если decoding confidence < `0.70`, считать payload неуверенным и отправлять в `REVIEW`.
4. Если decoding confidence >= `0.70`, прогнать декодированный текст через все тематические регламенты.
5. Определить, есть ли подтвержденный нарушающий payload.
6. Принять решение:
- обход + подтвержденный payload -> `REJECT`;
- обход без подтверждения payload -> `REVIEW`;
- стиль без попытки обхода -> `APPROVE`.

## Таблица решений (детерминированная)
- `REJECT`:
- Любой `EVASION_*` + подтвержденное нарушение из другого регламента.
- Или `EVASION_OBFUSCATED_LINK` с явной вредоносной/запрещенной целью.
- `REVIEW`:
- `EVASION_LEET|EVASION_WORD_SPLIT|EVASION_EMOJI_SPAM` без уверенного payload.
- Или неуспешная/пограничная декодировка потенциально нарушающего блока.
- `APPROVE`:
- Нестандартное оформление без признаков маскировки нарушающего смысла.

## Приоритеты и мультиразметка
- Формат: `primary_reason_code` + `secondary_reason_codes[]`.
- Приоритет:
1. `EVASION_OBFUSCATED_LINK`
2. `EVASION_WORD_SPLIT`
3. `EVASION_LEET`
4. `EVASION_EMOJI_SPAM`
- Если обход скрывает угрозу/незаконный призыв, primary определяется внешним регламентом (например, `ILLEGAL_INCITEMENT`), а evasions идут во вторичные.

## Reason codes
- `EVASION_LEET`: замена символов (`4`, `@`, `1`) для обхода словарей.
- `EVASION_WORD_SPLIT`: искусственные разрывы слова символами/пробелами.
- `EVASION_EMOJI_SPAM`: избыточный emoji/спецсимволный шум как маскировка.
- `EVASION_OBFUSCATED_LINK`: скрытая или искаженная ссылка.

## Примеры
- `REJECT`: обфусцированная ссылка на запрещенный ресурс с восстановленным payload.
- `REVIEW`: строка в base64, где декодирование неуверенно.
- `REVIEW`: `пр0д@м` без прочих нарушающих сигналов.
- `APPROVE`: креативный стиль с эмодзи без маскировки нарушений.

## Edge cases
- Игровой сленг и мемный стиль не считать обходом без явной цели скрыть нарушение.
- Редкие слова с апострофами/дефисами не интерпретировать как `WORD_SPLIT` автоматически.
- OCR-артефакты (случайные спецсимволы) требуют понижения уверенности и `REVIEW`.
- Декодирование должно быть ограничено безопасными, предсказуемыми методами без выполнения кода.

## Тестовая матрица
- T1: `l33t` + восстановленное токсичное слово -> `REJECT` + внешний reason.
- T2: обфусцированный URL на вредный ресурс -> `REJECT`, `EVASION_OBFUSCATED_LINK`.
- T3: word-split без подтвержденного payload -> `REVIEW`, `EVASION_WORD_SPLIT`.
- T4: emoji spam без нарушений -> `REVIEW` или `APPROVE` по интенсивности.
- T5: творческий сленг без обхода -> `APPROVE`.
- T6: decoding confidence < 0.7 -> `REVIEW`.
- T7: FN-контроль: mixed alphabet должен нормализоваться и детектироваться.
- T8: FP-контроль: редкие, но легитимные символы не должны приводить к `REJECT`.
