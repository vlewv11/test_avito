# Регламент: Спам и реклама

## Цель
Отсекать контент, который использует отзывы как рекламный, реферальный или массовый спам-канал вместо описания пользовательского опыта.

## Технические зависимости и контракт
- `ad_cta_patterns`: паттерны рекламных призывов (`купи`, `переходи`, `пиши`, `подписывайся`, `промокод`).
- `referral_patterns`: паттерны реферальных кодов/ссылок (`ref=`, `invite`, `promo`, `utm_`).
- `url_extractor`: нормализованный список URL `{raw_url, normalized_domain, path, query}`.
- `similarity_engine`: модуль кластеризации текстов, возвращает `template_score 0.0..1.0` и `cluster_size`.
- `message_frequency`: поведенческий сигнал числа похожих сообщений за окно времени.

Минимальный формат:
```json
{
  "ad_cta_patterns": ["переходи по ссылке", "пиши в директ"],
  "referral_patterns": ["ref=", "promo"],
  "similarity": {"template_score": 0.91, "cluster_size": 14}
}
```

## Термины и определения
- **CTA (Call To Action)**: явный призыв к действию в пользу покупки/перехода/контакта.
- **Реферальная механика**: контент, стимулирующий регистрацию/покупку по коду автора.
- **Шаблонный спам**: повторяющийся почти идентичный текст, публикуемый массово.
- **Легитимное упоминание бренда**: название бренда/магазина в рамках описания личного опыта.

## Нормализация входа
- Lowercase, унификация пробелов, разворачивание сокращенных URL при возможности.
- Нормализация домена (`www.`, `m.` удаляются), параметры сортируются для сравнения ссылок.
- Текст очищается от повторяющихся символов, но сохраняются токены `#`, `%`, валюты для оценки промо-контекста.

## Алгоритм проверки
1. Извлечь URL и классифицировать по домену: официальный объект отзыва / сторонний коммерческий / сокращатель.
2. Найти CTA и промо-маркеры в тексте.
3. Проверить наличие реферальных признаков в URL/query и тексте.
4. Рассчитать `template_score` и `cluster_size` по похожим отзывам.
5. Выставить риск:
- высокий: CTA + сторонняя ссылка/рефкод или массовый шаблон;
- средний: промо-лексика без прямого CTA;
- низкий: рассказ об опыте без продвижения.
6. Применить детерминированную таблицу решений.

## Таблица решений (детерминированная)
- `REJECT`:
- Есть `SPAM_REFERRAL`.
- Или `SPAM_LINK_FARM` (>= 2 внешних рекламных ссылки или одна явная реферальная).
- Или `SPAM_TEMPLATE` при `template_score >= 0.85` и `cluster_size >= 5`.
- Или явный `AD_PROMOTION` с CTA и внешним контактом.
- `REVIEW`:
- Есть промо-маркеры, но нет явного CTA.
- Или `template_score` в диапазоне `0.70..0.84`.
- Или есть одна внешняя ссылка без признаков реферальности.
- `APPROVE`:
- Нет спам/рекламных reason-кодов.
- Упоминание бренда/магазина относится к фактическому опыту.

## Приоритеты и мультиразметка
- Формат: `primary_reason_code` + `secondary_reason_codes[]`.
- Приоритет:
1. `SPAM_REFERRAL`
2. `SPAM_LINK_FARM`
3. `SPAM_TEMPLATE`
4. `AD_PROMOTION`
- Если одновременно есть рефкод и шаблонность, `primary = SPAM_REFERRAL`, `secondary` включает `SPAM_TEMPLATE`.

## Reason codes
- `SPAM_REFERRAL`: реферальный код/ссылка, мотивирующая действия в пользу автора.
- `SPAM_LINK_FARM`: набор коммерческих ссылок, не относящихся к отзыву.
- `SPAM_TEMPLATE`: массово повторяющийся шаблонный текст.
- `AD_PROMOTION`: прямой рекламный призыв без реферальной механики.

## Примеры
- `REJECT`: "Переходите по ссылке и берите со скидкой, промокод IVAN10".
- `REJECT`: одинаковый текст в десятках отзывов с разными аккаунтами.
- `REVIEW`: "Можно дешевле найти в интернете" без ссылок и CTA.
- `APPROVE`: "Купил в этом магазине, доставили за 2 дня".

## Edge cases
- Одна ссылка на официальный сайт производителя может быть допустима как источник контекста.
- Фраза "рекомендую" сама по себе не реклама без CTA/выгоды для автора.
- Упоминание цены не является спамом, если встроено в опыт покупки.
- Короткие отзывы могут быть схожими, но без массового повторения и CTA не считаются `SPAM_TEMPLATE`.

## Тестовая матрица
- T1: CTA + рефссылка -> `REJECT`, `SPAM_REFERRAL`.
- T2: 3 внешних коммерческих ссылки -> `REJECT`, `SPAM_LINK_FARM`.
- T3: template_score 0.9 и cluster_size 10 -> `REJECT`, `SPAM_TEMPLATE`.
- T4: промо-лексика без CTA -> `REVIEW`, `AD_PROMOTION`.
- T5: нейтральное упоминание бренда -> `APPROVE`.
- T6: один официальный URL без промо -> `APPROVE`.
- T7: пограничный template_score 0.75 -> `REVIEW`.
- T8: FP-контроль: "советую к покупке" в личном отзыве без ссылок/кода -> `APPROVE`.
